# Центр перепродажи: LIS-SKINS → Steam + FunPay

Один центр, который запускает и объединяет двух торговых ботов:

| Бот | Что делает | Где код |
|---|---|---|
| **LisBot** (Node.js) | Закупает предметы CS2 на LIS-SKINS по низу рынка (скан + мгновенная покупка новых лотов, RTBA), принимает трейды и после Trade Protection продаёт на Торговой площадке Steam | `bots/lisbot` |
| **MannBot** (Python) | Продаёт ключи Mann Co. на FunPay: ведёт сделку в чате заказа, отправляет трейд-оффер, держит цену конкурентов (RTBA), антифрод, CRM заказов | `bots/mannbot` |
| **Центр** (Python) | Запускает обоих ботов, следит за ними и перезапускает при сбоях, показывает общую панель: состояние, ключевые цифры, тревоги, журналы, управление | `center/` |

## Как устроено

```
                 ┌──────────────── Центр (python -m center), панель :8800 ───────────────┐
                 │  воркеры: запуск, проверка здоровья, перезапуск с паузой, журналы     │
                 │  сводка и тревоги обоих ботов · журнал событий center.sqlite3          │
                 └───────┬─────────────────────────────────────────────────────┬─────────┘
          процесс node   │  HTTP API + чтение базы                 процесс python │  HTTP API + чтение базы
                 ┌───────▼────────┐                                   ┌────────▼────────┐
                 │ LisBot  :8802  │  своя панель, своя база            │ MannBot  :8801  │
                 │ src/index.js   │  center-data/lisbot/data           │ app.launcher    │
                 └────────────────┘                                   └─────────────────┘
```

* Каждый бот работает отдельным процессом, как и раньше, со своей панелью и базой. Торговая логика ботов не переписывалась: центр общается с ними через их собственные веб-API и читает их базы только на чтение.
* Если бот упал, центр перезапускает его с растущей паузой (2 с → 5 мин). Если бот падает сразу после запуска 5 раз подряд, перезапуски прекращаются и в журнал центра пишется критическое событие.
* Если LisBot сообщает, что не заполнены настройки, центр показывает «нужна настройка» со списком того, чего не хватает, и не перезапускает его впустую.
* Кнопка «Открыть панель бота» открывает полную панель LisBot или MannBot уже со входом.

## Запуск

Нужны **Python 3.11+** и **Node.js 20+** (Node нужен только LisBot).

* **Windows, готовое приложение:** скачайте `Center-Windows-x64-portable.zip` (GitHub Actions → «Center Windows» → артефакт), распакуйте и запустите `Центр.vbs`. Python и Node.js уже внутри, центр работает в фоне со значком у часов (правый клик: панель, папка данных, выход). Собрать самому: `python packaging/build_center_windows.py`.
* **Windows из исходников:** запустите `Center.bat`. Он сам поставит Python-пакеты и зависимости LisBot, затем откроет панель в браузере.
* **VPS 24/7 в Docker:** `CENTER_SECRET_KEY=длинный-пароль docker compose up -d`, панели слушают 127.0.0.1 сервера, заходить через SSH-туннель (подробности в `docker-compose.yml`).
* **Linux / macOS / VPS без Docker:** `./center.sh` (на сервере: `./center.sh --no-browser --host 0.0.0.0`).
* Вручную: `pip install -r requirements.txt`, `cd bots/lisbot && npm ci --omit=dev`, затем `python -m center`.

Посмотреть без аккаунтов: `python -m center --demo`. MannBot запустится с эмуляцией FunPay и Steam и демо-заказами, LisBot — с эмуляцией LIS-SKINS и Steam (`bots/lisbot/src/emu`): он сам покупает лоты, принимает трейды и продаёт на ТП в сжатые сроки, продолжая демо-историю сделок за месяц, которая наполняет аналитику, CRM, RTBA и бэктест. Демо-данные пересоздаются при каждом запуске и лежат отдельно, в `center-data/demo`.

### Первая настройка

Пошаговая инструкция первого запуска с настоящими аккаунтами (тестовый режим, малые лимиты, что проверить, типичные ошибки): [docs/first-launch.md](docs/first-launch.md).

1. **LisBot:** в карточке LisBot нажмите «Подключения» и введите ключ API LIS-SKINS, логин и пароль Steam, `shared_secret` и `identity_secret` из maFile, трейд-ссылку и, по желанию, Telegram. Параметры стратегии меняются во вкладке «Настройки» панели LisBot.
2. **MannBot:** кнопка «Настройки» в карточке MannBot: лоты FunPay, golden_key, maFile Steam, Telegram, RTBA, риск-система и остальные поля панели MannBot. Новые секреты сохраняются в зашифрованном хранилище, и центр перезапускает процесс MannBot.
3. Оба бота стартуют в **тестовом режиме** и ничего не покупают и не продают. Боевой режим включается в панели каждого бота.

### Где лежат данные

Всё хранится в `center-data/` рядом с программой (или в папке из `--home` / `$CENTER_HOME`):

```
center-data/
  center.yaml        порт панели, токен входа, какие боты запускать, параметры перезапуска
  center.sqlite3     журнал событий центра, история состояния ботов, уведомления
  logs/              вывод центра и каждого бота
  secrets.dat        все ключи и пароли в зашифрованном виде (см. ниже)
  lisbot/            config.json (стратегия), data/ (база и логи LisBot)
  mannbot/           config.yaml (секреты в нём — ссылки ${CENTER_MB_…}) и data/ MannBot
```

**Секреты.** Ключ LIS-SKINS, пароль и ключи Steam, golden_key FunPay, токены Telegram и ключи Claude API лежат в `secrets.dat`, а не открытым текстом. На Windows файл зашифрован DPAPI текущего пользователя (как в Electron-версии LisBot): расшифровать его может только этот пользователь на этом компьютере, при переносе на другой ПК ключи придётся ввести заново. На Linux, в Docker и на macOS используется Fernet с ключом из `CENTER_SECRET_KEY` (иначе ключ создаётся в `center-data/secret.key`). Старые `lisbot/secrets.env` и секреты в `mannbot/config.yaml` переносятся в хранилище автоматически при первом запуске; если секрет ввести в собственной панели MannBot, центр перенесёт его при следующем перезапуске бота.

**Остановка ботов.** Кнопка «Выход», значок в трее, `docker stop` и закрытие окна консоли сначала просят ботов завершиться самих через их API (`POST /api/shutdown` у LisBot, «Выход» у MannBot), чтобы они дописали базы и закрыли сессии, и только если бот не успел, процесс завершается принудительно. На Windows процессы ботов привязаны к центру (Job Object): если центр упадёт, боты не останутся висеть в фоне.

Чтобы перенести центр на другой компьютер, достаточно скопировать эту папку (резервные копии центр делает сам, см. «Резервные копии»). В `center.yaml` можно выключить бота (`workers.lisbot.enabled: false`), отключить автозапуск или поменять порты.

### Аналитика перепродажи

Блок «Аналитика перепродажи» в панели центра считает общий P&L обоих ботов в рублях или долларах за 7/30/90 дней или за всё время: выручку, расходы, прибыль, ROI, капитал в работе и оборот капитала. Ниже — график прибыли, выручки и числа сделок по дням, таблица предметов LisBot (ROI, удержание, точность прогноза цены) и воронка заказов MannBot (время сделки, доля подтверждений и возвратов). Кнопки CSV и XLSX выгружают все сделки центра за выбранный период.

* Курс USD→RUB: курс LisBot (если кошелёк Steam в рублях), иначе ЦБ РФ, без сети — `analytics.fallback_usd_rub`. Зафиксировать курс: `analytics.usd_rub: 92.5` в `center.yaml`.
* Прибыль MannBot считается из `rtba.cost_per_key` (себестоимость ключа) и `rtba.funpay_fee_pct` (комиссия FunPay) в настройках MannBot. Пока себестоимость не задана, панель показывает предупреждение и в итог входит только выручка MannBot.
* API: `/api/analytics/pnl?days=30`, `/api/analytics/daily?days=30&currency=RUB`, `/api/analytics/bot/lisbot`, `/api/analytics/bot/mannbot`, `/api/analytics/export.csv`, `/api/analytics/export.xlsx` (`days=all` — за всё время).

### CRM

Блок «CRM» в панели центра — единый список сделок обоих ботов: предметы LisBot (покупка → продажа) и заказы MannBot на FunPay. Есть поиск по предмету, ID, покупателю, Steam ID, заметке и тегу, фильтры по боту, периоду и состоянию сделки (в работе, требует внимания, завершена, не состоялась), сортировка по дате, сумме и прибыли и выгрузка выборки в CSV. Тестовые сделки LisBot (dry-run) скрыты, пока не отмечен флажок. По клику открывается карточка сделки с историей событий, перепиской с покупателем и заметкой.

Вкладка «Покупатели FunPay» показывает покупателей MannBot: заказы, подтверждения, возвраты, потраченную сумму, отзывы и риск-скоринг центра от 0 до 100 (возвраты, блокировки антифродом, Steam-аккаунт общий с другими покупателями, неподтверждённые заказы, низкие отзывы; постоянным покупателям риск снижается). В карточке покупателя можно поменять заметку и теги и добавить его в чёрный список.

* Центр читает базы ботов только на чтение. Заметки, теги и чёрный список записываются через API ботов (LisBot `POST /api/item`, MannBot `POST /api/orders/{id}` и `POST /api/customers/{id}`), поэтому для сохранения бот должен быть запущен.
* У предметов LisBot есть заметка и теги, у заказов MannBot только заметка; теги MannBot ставятся покупателю.
* API: `/api/crm/deals?q=&bot=&group=&days=&dry=1&sort=&dir=&limit=&offset=`, `/api/crm/deals.csv`, `/api/crm/deals/{lisbot|mannbot}/{id}` (GET и POST `{notes, tags}`), `/api/crm/customers?q=&risk=&tag=&sort=`, `/api/crm/customers/{funpay_id}` (GET и POST `{notes, tags, blacklisted}`).

### Мониторинг

Раздел «Мониторинг» панели центра показывает аптайм и время ответа каждого бота за 24 часа, 7 или 30 дней, а также все уведомления центра.

* **Уведомления в Telegram:** падение или перезапуск бота, «бот не отвечает» (несколько проверок подряд), критические тревоги ботов, аварийное выключение центра в прошлый раз. Одинаковые уведомления не повторяются чаще раза в 15 минут, в тихие часы некритичное копится и приходит одним сообщением. Токен и chat id задаются кнопкой «Настройки уведомлений»; если их нет, центр берёт Telegram из подключений LisBot.
* **Сторожевой пинг:** укажите URL проверки с healthchecks.io (или похожего сервиса). Центр пингует его раз в минуту; если пинги пропали, значит выключился сам центр или компьютер, и сервис сообщит об этом.
* **Ежедневный отчёт** в заданное время: аптайм, перезапуски, тревоги и показатели обоих ботов за сутки. Кнопка «Отчёт за сутки» показывает его сразу.
* **Недельный отчёт** по понедельникам (`monitor.weekly_report`): сделки, выручка и прибыль за 7 дней в сравнении с прошлой неделей, лучшие и убыточные предметы LisBot, аптайм и склад. Кнопка «За неделю» и команда `/week`.
* Тревоги ботов подтверждаются прямо в центре (кнопка ✓ или «Подтвердить все»), подтверждение уходит в самого бота.

* **Команды в Telegram** (если у центра свой Telegram-бот, не тот, что у LisBot): `/status`, `/report`, `/week`, `/stock`, `/proposals`, `/pause lisbot|mannbot`, `/resume …`, `/buypause`, `/buyresume`, `/backup`. Предложения координатора приходят с кнопками «Одобрить» и «Отклонить»; лимиты требуют второго нажатия, а боевой режим и вывод денег одобряются только в панели. Команды принимаются только из указанных chat id; выключаются флажком в настройках уведомлений (`monitor.telegram.commands`).

Все параметры лежат в разделе `monitor` файла `center.yaml`.

### Склад

Блок «Склад сейчас» в аналитике показывает, что лежит у ботов прямо сейчас.

* **LisBot:** каждый купленный и ещё не проданный предмет: где он (Trade Protection, на ТП…), сколько дней лежит, цена покупки и сколько бот получит за него по последней оценке рынка (после комиссии Steam), бумажная прибыль или убыток. Флаги «долго лежит» (дольше `sell.maxHoldDaysAlert` LisBot или `inventory.lis_old_days`), «в минусе» и «лимит перевыставлений» поднимают такие предметы наверх; ИИ-координатор предлагает их разобрать.
* **MannBot:** ключи на складе, скорость продаж за 14 дней и на сколько дней их хватит. Если меньше чем на `inventory.mann_days_warn` дней (по умолчанию 3), центр присылает уведомление раз в сутки. Строки о складе есть и в ежедневном отчёте.
* API: `GET /api/inventory`.

### Резервные копии

Раздел «Резервные копии» панели центра. Каждый день в `backup.time` (по умолчанию 04:00, а если компьютер был выключен — при следующем запуске) центр сохраняет `center-backup-ГГГГММДД-ЧЧММСС.zip` в `center-data/backups/` или в папку из настроек (удобно указать папку Яндекс Диска или Google Drive). Хранится `backup.keep` копий каждого вида (по расписанию, вручную, перед восстановлением).

* В копии вся папка данных: `center.yaml`, `center.sqlite3`, `secrets.dat`, настройки и базы LisBot и MannBot. Базы снимаются через backup API SQLite, поэтому копия целостна, даже пока боты торгуют, и каждая проверяется `integrity_check`. Журналы, `-wal`/`-shm` и `secret.key` не копируются: ключи в копии остаются зашифрованными (на Windows их расшифрует только этот пользователь Windows, на Linux нужен тот же `CENTER_SECRET_KEY` или файл `secret.key`).
* Неудачная копия приходит уведомлением в Telegram и отмечается в ежедневном отчёте.
* **Восстановление:** кнопка «Восстановить» у копии останавливает ботов и закрывает центр; при следующем запуске копия восстанавливается до старта ботов. Или при закрытом центре: `python -m center --restore center-data/backups/<копия>.zip`. Текущие данные перед восстановлением сохраняются копией `…-before-restore.zip`.
* API: `GET /api/backup`, `POST /api/backup/run`, `GET|POST /api/backup/settings`, `GET /api/backup/download/<имя>`, `POST /api/backup/restore {name, confirm: "ВОССТАНОВИТЬ"}`.


### ИИ-координатор

Раздел «ИИ-координатор» панели центра следит за обоими ботами, раз в день присылает брифинг и предлагает действия. Решения принимает FrayZ: координатор сам делает только то, что ему разрешено, и только при явной аномалии.

* **Полномочия** (кнопка «Полномочия и ключ», раздел `coordinator.permissions` в `center.yaml`): «делает сам», «предлагает», «нужно подтверждение», «только вручную», «выключено». По умолчанию сам он ставит на паузу только закупки LisBot; паузу торговли, возобновление, перезапуск, подтверждение тревог и настройки стратегии он предлагает; лимиты и боевой режим всегда требуют подтверждения, а вывод денег центр не выполняет вообще (🔒 эти уровни нельзя ослабить).
* **Сторож аномалий** (без ИИ, раз в минуту): всплеск трат LisBot за час относительно среднего за неделю и серия убыточных продаж подряд ставят закупки LisBot на паузу; много возвратов MannBot за сутки и окончательно упавший бот дают предложение. Пороги — `coordinator.anomaly`.
* **Брифинг** в `coordinator.briefing.time` (по умолчанию 09:05) и по кнопке: факты из аналитики и мониторинга, выводы и рекомендации. С ключом Claude API (поле «Ключ Claude API») брифинг пишет Claude; без ключа и в демо — короткая сводка по правилам. ИИ ничего не выполняет: его советы попадают в «Ждут вашего решения». Там же можно задать координатору вопрос.
* Уведомления (сделанные действия, предложения по аномалиям, брифинг) идут через Telegram мониторинга. Одобрить или отклонить предложение — в панели. Все решения хранятся в журнале (`coord_decisions` в `center.sqlite3`).
* API: `/api/coordinator/status`, `/api/coordinator/briefing`, `/api/coordinator/ask`, `/api/coordinator/check`, `/api/coordinator/decisions/<id>/approve|reject`, `/api/coordinator/settings`.

## Боты по отдельности

Каждого бота по-прежнему можно запускать и собирать отдельно, как в исходных проектах:

* LisBot: `bots/lisbot/README.md` (десктоп-приложение Electron с установщиком: `npm run build:win`).
* MannBot: `bots/mannbot/README.md` (портативная Windows-версия, Docker; сборка exe в GitHub Actions — workflow «Build MannBot»).

## Проверки

```
python -m pytest -q                        # центр
cd bots/mannbot && python -m pytest -q     # MannBot (30 тестов)
cd bots/lisbot && npm test                 # LisBot (26 тестов)
```

Все три набора запускаются в GitHub Actions на каждый пуш.

**Что не проверено:** работа ботов на настоящих LIS-SKINS, Steam и FunPay. Из среды разработки эти сайты недоступны, поэтому боты по умолчанию в тестовом режиме. Центр и оба бота проверены на Linux; на Windows центр ещё не запускался.
