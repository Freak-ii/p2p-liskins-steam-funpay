# Первый запуск центра с настоящими аккаунтами

Инструкция для раздела 0 плана: проверить LisBot и MannBot на настоящих LIS-SKINS, Steam и FunPay, сначала в тестовом режиме, потом на маленьких лимитах, и подтвердить, что центр работает на Windows. Всё ниже сверено с кодом ветки PR #10 и с пробным запуском центра на пустой папке данных.

Порядок такой: шаг 1 и 2 (около 10 минут), затем LisBot и MannBot можно настраивать параллельно. Тестовый режим стоит оставить хотя бы на сутки, прежде чем переходить к маленьким лимитам.

---

## Перед началом: что подготовить

| Что | Для кого | Где взять |
|---|---|---|
| Ключ API LIS-SKINS | LisBot | lis-skins.com → профиль → API |
| Логин и пароль Steam **аккаунта для ботов** (один на оба) | LisBot и MannBot | — |
| maFile этого аккаунта (Steam Desktop Authenticator), **без шифрования** | LisBot | папка `maFiles` у SDA. Если файл зашифрован: SDA → Manage Encryption → снять шифрование |
| Трейд-ссылка этого аккаунта | LisBot | Steam → Инвентарь → Предложения обмена → «Кто может отправлять мне предложения обмена» → ссылка |
| cookie `golden_key` FunPay | MannBot | браузер, где вы вошли на funpay.com → F12 → Application (Приложение) → Cookies → `https://funpay.com` → `golden_key` |
| `offer_id` вашего лота с ключами | MannBot | открыть свой лот, число после `offer?id=` в адресе |
| Два Telegram-бота (токены от @BotFather) и ваш chat id (@userinfobot) | уведомления | см. «Telegram» ниже |
| Ключ Claude API | ИИ-координатор и ИИ-агент MannBot | console.anthropic.com → API Keys |

> ℹ️ **Оба бота работают на одном аккаунте Steam.** Каждый входит в Steam сам и подтверждает только свои действия: LisBot свои лоты и ордера на торговой площадке, MannBot свои обмены с покупателями. Перед отправкой ключей покупателю MannBot записывает обмен в центр (кому и какие ключи), и LisBot пропускает только такие обмены. Любой другой исходящий обмен или чужое мобильное подтверждение LisBot, как и раньше, считает признаком взлома: отменяет его и делает аварийную остановку (`UNKNOWN_OUTGOING_TRADE`, `UNKNOWN_CONFIRMATION`). Поэтому не торгуйте вручную с этого аккаунта, пока боты запущены. Если хотите по-старому развести ботов по двум аккаунтам, это тоже работает: впишите в `center.yaml` раздел `steam: {shared_account: false}`.

> ⚠️ **Не покупайте ничего вручную на LIS-SKINS с того же ключа API**, пока LisBot работает: уменьшение баланса не через бота он считает утечкой ключа (`UNKNOWN_SPEND`) и останавливается.

**Telegram.** LisBot и MannBot оба принимают команды из Telegram и читают обновления своего бота. Если дать им один и тот же токен, они будут перехватывать сообщения друг у друга. Сделайте у @BotFather двух ботов: одного для LisBot, второго для MannBot. Уведомлениям центра (мониторинг и координатор) отдельный бот не нужен: если в центре токен не задан, он берёт Telegram из подключений LisBot. Перед проверкой напишите `/start` каждому своему боту, иначе Telegram не даст боту написать вам первым.

## Шаг 1. Скачать и распаковать

1. Откройте [выпуски центра](https://github.com/Freak-ii/p2p-liskins-steam-funpay/releases) и в самом свежем скачайте `Center-Windows-x64-portable.zip` (блок **Assets**).
2. Распакуйте архив. Сборки из PR, которые ещё не выпущены, лежат во вкладке PR → Checks → **Center Windows** → Summary → Artifacts; там GitHub отдаёт zip внутри zip, распакуйте оба.
3. Положите папку `Center` в путь **без кириллицы и пробелов**, например `C:\Center`. Python и Node.js уже внутри, ставить ничего не нужно.

Внутри:

```
C:\Center\
  Центр.vbs               основной запуск: в фоне, значок у часов
  Центр (консоль).bat     то же, но с окном журнала (удобно в первый раз)
  Центр DEMO.bat          демо без аккаунтов, данные отдельно
  ПРОЧТИ МЕНЯ.txt
  data\                   всё ваше: настройки, базы, журналы, secrets.dat
  app\  runtime\          код и встроенные Python/Node
```

## Шаг 2. Первый запуск (пункт раздела 0 «центр на Windows»)

1. Первый раз запустите **«Центр (консоль).bat»**: видно журнал, и если что-то пойдёт не так, окно не закроется. Дальше можно пользоваться «Центр.vbs».
2. Если появится SmartScreen «Windows защитила ваш компьютер»: «Подробнее» → «Выполнить в любом случае». Сборка без цифровой подписи, это ожидаемо.
3. Откроется браузер с панелью центра `http://127.0.0.1:8800/` (вход уже выполнен по ссылке с токеном; сам токен лежит в `data\center.yaml`, поле `center.token`).

**Как понять, что всё в порядке** (так выглядит пустая папка данных в пробном запуске):

- карточка **MannBot · FunPay**: значок «работает», строка «Торговля: остановлена · тестовый режим». Это нормально: процесс MannBot поднялся, торговлю вы запустите сами после настройки;
- карточка **LisBot · LIS-SKINS → Steam**: значок «нужна настройка» и список того, чего не хватает (`LIS_API_KEY не задан; STEAM_ACCOUNT_NAME / STEAM_PASSWORD не заданы; …`). Центр не перезапускает его впустую, пока ключей нет;
- у часов значок центра. Жёлтый значок значит, что одному из ботов нужна настройка, и сейчас так и должно быть.

Если хочется сначала посмотреть панель с данными, запустите «Центр DEMO.bat»: оба бота торгуют на эмуляторах, ваши настройки и `data\` это не трогает. Перед настоящим запуском закройте демо (кнопка «⏻ Выход»).

## Шаг 3. LisBot: подключения и тестовый режим

### 3.1. Ввести ключи

Панель центра → карточка LisBot → **«Подключения»**:

| Поле | Что вписать |
|---|---|
| Ключ API LIS-SKINS | ключ из профиля LIS-SKINS |
| Логин Steam, Пароль Steam | аккаунт для LisBot |
| shared_secret, identity_secret | откройте maFile Блокнотом и скопируйте значения полей `"shared_secret"` и `"identity_secret"` (без кавычек). Загрузки файла в этом окне нет, только копирование |
| Трейд-ссылка Steam | полная ссылка `https://steamcommunity.com/tradeoffer/new/?partner=…&token=…` |
| Telegram: токен, chat id | бот №1 и ваш chat id (необязательно) |

«Сохранить и перезапустить». Ключи уходят в `data\secrets.dat`, зашифрованный Windows DPAPI: открыть его может только ваш пользователь Windows на этом компьютере.

> Пароль Steam LisBot использует только для первого входа, дальше живёт на токене. Есть лимит **4 входа в сутки** (`steam.maxLoginsPerDay`), поэтому не перезапускайте бота много раз подряд с неверным паролем: проверьте поля один раз внимательно.

### 3.2. Убедиться, что тестовый режим включён

LisBot по умолчанию в **DRY-RUN**: считает, что купил бы, но реальных покупок и продаж не делает. В карточке LisBot должно быть «тестовый режим (ничего не покупает и не продаёт)», а в журнале бота строка `Бот запущен в режиме DRY-RUN`. Если там «боевой режим», не продолжайте, а сначала выключите его (см. 3.4).

### 3.3. Что проверить в тестовом режиме (пункт раздела 0 «LisBot в dryRun»)

Через 2–5 минут после запуска, кнопка **«Открыть панель бота ↗»** в карточке LisBot:

- [ ] **Steam вошёл.** В журнале нет `STEAM_LOGIN` / `STEAM_START`, вкладка «Тревоги» пустая. Карточка в центре: «Торговля: работает», а не «аварийная остановка».
- [ ] **LIS-SKINS отвечает.** В карточке центра появился «Баланс LIS, $» (не прочерк). Нет тревоги `LIS_AUTH`.
- [ ] **Оценки считаются.** Вкладка «Вотчлист»: у предметов появляется оценка и решение бота с причиной. Одна оценка = 2 медленных запроса к Steam, так что первые оценки идут несколько минут.
- [ ] **Симуляция покупок.** Вкладка «Предметы» → «симуляция»: записи «купил бы» с ожидаемой прибылью. Пустой список в первый час не ошибка: бот покупает только по низу рынка и с ROI от 8%.
- [ ] **WebSocket LIS (RTBA).** Вкладка «Система» → счётчик «WS событий» растёт. В центре страница **«RTBA и лимиты»** показывает решения по новым лотам. Если счётчик стоит на нуле больше 10–15 минут, напишите мне: возможно, у LIS канал называется иначе (`lis.wsChannels`), документация LIS тут неполная.
- [ ] **Telegram LisBot** (если задали): пришло «✅ Бот запущен в режиме DRY-RUN», бот отвечает на `/status`.

Оставьте DRY-RUN на сутки и посмотрите, разумны ли «купил бы»: цены, предметы, ожидаемая прибыль.

### 3.4. Маленькие лимиты и боевой режим

Сначала лимиты, потом боевой режим. В панели LisBot, вкладка **«Настройки»**, предлагаю для первого прогона:

| Настройка | Значение для пробы | По умолчанию |
|---|---|---|
| Макс. цена предмета, $ | 2 | 60 |
| Лимит трат в час, $ | 3 | 60 |
| Лимит трат в день, $ | 5 | 300 |
| Макс. сумма в товаре, $ | 10 | 1500 |
| Макс. штук предмета в день | 1 | 3 |
| Стоп при дневном убытке, $ | 3 | 40 |

Те же лимиты можно задать в центре: «RTBA и лимиты» → план → «Применить к ботам». Вотчлист на первый раз стоит сузить до 2–3 дешёвых ликвидных предметов (кейсы) во вкладке «Вотчлист».

Затем во вкладке «Настройки» снимите галочку **«Режим симуляции (DRY-RUN)»** и подтвердите. Карточка в центре покажет красное «боевой режим».

**Что проверить на малых лимитах:**

- [ ] первая настоящая покупка: на LIS списались деньги, во вкладке «Предметы» предмет со статусом покупки, в Telegram 💰;
- [ ] пришёл обмен от бота LIS, LisBot принял его сам, предмет появился в инвентаре Steam аккаунта LisBot;
- [ ] через 7 дней Trade Protection (плюс 30 минут запаса) LisBot сам выставил предмет на Торговую площадку и подтвердил лот. Эта часть проверки займёт неделю, это свойство Steam, а не бота;
- [ ] после продажи в аналитике центра появилась сделка с прибылью.

## Шаг 4. MannBot: настройки, тестовый режим, один лот

### 4.1. Ввести настройки

Панель центра → карточка MannBot → **«Настройки»** (кнопка видна, когда процесс MannBot «работает»):

1. **Лоты FunPay с ключами:** `offer_id` вашего лота. `node_id` 1808 и `game_id` 435 (TF2) уже подставлены, «ключей за 1 шт.» обычно 1.
2. **maFile Steam Guard:** выберите тот же maFile, что и для LisBot. Он сам заполнит логин, SteamID64, shared_secret и identity_secret.
3. **FunPay → golden_key:** значение cookie.
4. **Steam → Пароль Steam.**
5. **Основное → Тестовый режим (dry-run):** галочка должна стоять (так по умолчанию).
6. **Telegram:** включить, токен бота №2, ваш chat id в «chat_id администраторов».
7. **RTBA — автоцена:** пока оставьте выключенной. Но впишите **«Себестоимость ключа, ₽»**: без неё аналитика центра не посчитает прибыль MannBot.

«Сохранить». Если в окне осталось «Не хватает: …», допишите перечисленное. Секреты уходят в зашифрованное хранилище центра, процесс MannBot перезапустится сам.

> Не нажимайте «Выйти» на funpay.com в браузере, из которого взяли `golden_key`: выход обычно делает cookie недействительной. Просто закройте вкладку.

### 4.2. Запустить в тестовом режиме (пункт раздела 0 «MannBot в тестовом режиме»)

Карточка MannBot → **«Запустить торговлю»**. В тестовом режиме MannBot читает FunPay и Steam и ведёт CRM, но ничего не отправляет: ни сообщений, ни обменов, ни изменений лота.

- [ ] «Торговля: работает · тестовый режим», в журнале MannBot нет ошибок входа FunPay или Steam;
- [ ] в карточке «Ключей на складе» показывает число ключей в инвентаре (не прочерк): значит Steam читается;
- [ ] новые заказы и чаты с покупателями появляются в CRM центра и в панели MannBot, хотя бот им не отвечает;
- [ ] Telegram MannBot: приходят уведомления, бот отвечает на `/status`;
- [ ] страница «RTBA и лимиты» → MannBot показывает цены конкурентов и какую цену бот поставил бы.

Пока бот в тестовом режиме, заказы на FunPay обрабатывайте вручную, как раньше.

### 4.3. Один лот вживую

1. В «Настройки» → FunPay поставьте **«Максимум показываемого наличия» = 1**: на лоте будет виден один ключ, и одновременно придёт максимум один заказ.
2. Снимите галочку **«Тестовый режим»**, «Сохранить». Карточка покажет «боевой режим».
3. Дождитесь одного настоящего заказа.

Что должно произойти:

- [ ] в чате заказа бот написал инструкцию и попросил трейд-ссылку;
- [ ] получив ссылку, отправил обмен и подтвердил его через maFile (без вас);
- [ ] после принятия обмена написал благодарность и попросил подтвердить заказ;
- [ ] заказ в CRM центра прошёл до «завершена», в аналитике появилась выручка и прибыль.

Если что-то не так, «Остановить торговлю» в карточке и доведите заказ вручную. После удачного заказа верните нормальное наличие и при желании включите RTBA с себестоимостью и минимальной маржой.

## Шаг 4б. Ключи за деньги кошелька Steam (по желанию)

Подробная инструкция с выбором цены, лимитов и разбором ошибок: [key-bridge.md](key-bridge.md).

LisBot продаёт скины на торговой площадке Steam, деньги копятся на кошельке. Он может сам покупать на эти деньги ключи Mann Co. в тот же инвентарь, а MannBot продаёт их на FunPay. Ключ, купленный на площадке, Steam разрешает передать только через 7 дней, поэтому MannBot начинает продавать его через неделю. По умолчанию покупка выключена. Включайте её только после того, как оба бота отработали в тестовом режиме.

1. **LisBot:** «Открыть панель бота ↗» → вкладка «Настройки» → поля «Мост ключей»: включите «ключи Mann Co. для MannBot» и «покупать ключи на ТП Steam», задайте максимальную цену ключа, сколько ключей в день и сколько оставлять на кошельке. Поле «трейд-ссылка аккаунта MannBot» оставьте **пустым**: ключи остаются в общем инвентаре.
2. В MannBot ничего настраивать не нужно.
3. Пока LisBot в тестовом режиме, он только пишет в журнал, что купил бы.

Что проверить:
- [ ] в карточке готовности пункт «Ключи с кошелька Steam» зелёный;
- [ ] в «Аналитике» → «Склад сейчас» видно, сколько ключей куплено и сколько ждут 7 дней;
- [ ] через 7 дней после первой покупки склад MannBot вырос на эти ключи.

## Шаг 7. Выход и повторный запуск

- [ ] Правый клик по значку у часов → «Выход (остановить ботов)» или «⏻ Выход» в панели. Через несколько секунд в Диспетчере задач не должно остаться `node.exe` и `python.exe` из `C:\Center`;
- [ ] снова «Центр.vbs»: оба бота поднимаются сами, LisBot не просит ключи заново.

- [ ] в разделе «Резервные копии» нажмите «Сделать копию сейчас» и, если пользуетесь Яндекс Диском или Google Drive, укажите их папку в «Расписание и папка»: тогда копии баз переживут и поломку компьютера.

После этого раздел 0 можно отмечать. Напишите в проект, что получилось, и я отмечу пункты в плане.

## Если что-то пошло не так

| Что видно | Причина | Что делать |
|---|---|---|
| LisBot «нужна настройка» после ввода ключей | не все поля заполнены или трейд-ссылка неполная | список под значком называет, чего не хватает; в трейд-ссылке должны быть и `partner`, и `token` |
| `STEAM_LOGIN` / `STEAM_START`, «Торговля: аварийная остановка» | неверный логин/пароль, не тот maFile, сбились часы Windows | проверьте поля в «Подключениях»; Параметры → Время → «Синхронизировать сейчас» (коды Steam Guard зависят от точного времени); затем «Продолжить / снять остановку» в карточке. Помните про 4 входа в сутки |
| `LIS_AUTH` | LIS не принял ключ API | новый ключ в «Подключениях» |
| `UNKNOWN_OUTGOING_TRADE`, `UNKNOWN_CONFIRMATION` | на аккаунте обмен или подтверждение не от ботов: ручная торговля, MannBot запущен без центра или взлом | торгуйте вручную только при остановленных ботах, MannBot запускайте из центра; если это не вы, смените пароль Steam и ключ Steam Web API |
| `UNKNOWN_SPEND` | баланс LIS уменьшился не через бота | если покупали сами, подтвердите тревогу и «Продолжить»; если нет, перевыпустите ключ LIS |
| «в maFile нет shared_secret/identity_secret» | maFile зашифрован | SDA → Manage Encryption → снять шифрование, взять файл заново |
| MannBot: «funpay.golden_key не задан» или ошибки входа FunPay | cookie не вписана или устарела | взять `golden_key` заново (вы могли выйти на сайте) |
| Бот в Telegram отвечает через раз или молчит, в журнале `409 Conflict` | один токен у двух ботов | разные боты @BotFather для LisBot и MannBot |
| «порт 8801/8802 занят другой программой» | что-то заняло порт, или остался процесс от прошлого запуска | закройте лишний `python.exe`/`node.exe` или поменяйте `workers.<бот>.port` в `data\center.yaml` |
| «ключи не расшифрованы» | папку `data\` перенесли на другой ПК или пользователя Windows | ключи придётся ввести заново: DPAPI привязан к пользователю и компьютеру |
| Ничего не открывается после «Центр.vbs» | ошибка при старте не видна без консоли | запустите «Центр (консоль).bat» и посмотрите текст; журналы в `data\logs\` |

Если застряли, пришлите в проект текст ошибки из журнала или файл из `data\logs\` (`center.log`, `lisbot.log`, `mannbot.log`). Перед отправкой пробегите их глазами, чтобы там не оказалось ключей или паролей.
