# Орбита: StarsCenter на сервере 24/7 с обновлением на ходу

**Орбита** — так называется вся система: Центр, все боты (StarsBot, MannBot, LisBot, ShopBot, TG Gift) и круги
денег между ними. Этот документ — про серверную часть: Орбита работает на VPS круглосуточно, а новые версии
ставятся без остановки торговли. Пульт позиций («снять позицию с орбиты» сразу со всех площадок) — отдельный
раздел Центра.

## Что даёт серверный режим

| | ПК (как сейчас) | Сервер (Орбита) |
|---|---|---|
| Работа | пока включён ПК и открыт Центр | 24/7, сама поднимается после перезагрузки VPS |
| Обновление | закрыть Центр, распаковать архив, запустить, нажать «Запустить» у каждого бота | новый коммит в ветке → через ≤5 минут ставится сам |
| Остановка торговли при обновлении | все боты стоят, пока вы обновляете | каждый бот перезапускается отдельно, на несколько секунд; панель Центра пропадает на 2–3 секунды |
| Сбой новой версии | разбираться вручную | бот сам возвращается на прежнюю версию, Центр тоже, в Telegram приходит тревога |
| Копии баз | раз в сутки | ещё и перед каждым обновлением (`/var/backups/orbita`) |

Правило «Центр сам ботов не запускает» сохраняется: после установки и переезда ботов запускаете вы,
кнопкой «Запустить». Обновление перезапускает только тех ботов, что уже работали.

## Как устроено обновление на ходу

```
 git push в ветку ─► orbita auto (таймер, раз в 5 мин)
                      1. собрать релиз /opt/orbita/releases/<время>-<sha>  (зависимости, проверка импорта, быстрые тесты)
                      2. копии всех баз SQLite → /var/backups/orbita/<время>
                      3. ссылка current → новый релиз
                      4. «эстафета»: старый Центр выходит, НЕ останавливая ботов ──► systemd сразу запускает новый Центр
                      5. новый Центр подхватывает работающих ботов и обновляет их по одному:
                         ShopBot → TG Gift → LisBot → MannBot → StarsBot,
                         каждый должен проработать 45 с без падений, иначе — откат этого бота и стоп
                      6. если что-то не так — Центр тоже возвращается на прежний релиз
```

* Боты пишут вывод прямо в файлы журналов (`/var/lib/orbita/logs/<бот>.log`), а не в процесс Центра,
  поэтому переживают его перезапуск. Новый Центр находит их по порту и токену и продолжает присматривать.
* Каждый бот знает, из какого релиза он запущен (в панели и в `orbita status`). Во время обновления
  боты могут недолго работать на разных версиях — поэтому изменения баз делаются только «добавлением»
  (новые таблицы и колонки), старая версия должна спокойно работать с новой базой.
* Бот перезапускается так же мягко, как кнопкой: дописывает базу, отдаёт аренду базы, закрывает сессии.
  StarsBot держит аренду базы (`engine_lease`), поэтому два экземпляра на одной базе не работают даже на миг.
  Незакрытые заказы FunPay никуда не деваются: новый процесс подбирает их из базы при старте.
* Почему не «ноль секунд»: на одном аккаунте FunPay, одной сессии Telegram и одном кошельке TON может работать
  только один процесс, иначе двойная выдача заказа. Поэтому каждый бот недоступен на время своего запуска
  (обычно 3–15 секунд), а остальные в это время торгуют.

## Сервер: что брать и сколько стоит

Нужно: **2 vCPU, 4 ГБ RAM, 40+ ГБ NVMe, Ubuntu 24.04**, Европа (Нидерланды, Германия, Финляндия): оттуда
без проблем работают FunPay, Fragment, Telegram и TON. Орбите хватает примерно 1,5 ГБ памяти (пять процессов
Python, Node.js для LisBot и Центр), остальное — запас и VPN. На 2 ГБ работать будет, но впритык.

| Вариант | Тариф | Цена в месяц | Оплата из РФ | Оговорки |
|---|---|---|---|---|
| **Aeza** (NL / DE / FI) | Shared vCPU, 2 vCPU / 4 ГБ | от €4,94 | карта РФ, СБП (по невыгодному курсу), крипта | в июле 2025 Aeza Group попала в санкционный список США (OFAC); бывали сбои в отдельных локациях, блокировки подсетей у российских провайдеров |
| **Hetzner** (DE / FI) | CX23, 2 vCPU / 4 ГБ / 40 ГБ | €5,49 + €0,50 за IPv4 (цены с 15.06.2026) | только иностранная карта/PayPal, проверка личности | лучший по надёжности, но клиентов из РФ обычно не принимают; CX-тарифы с лета 2026 часто «нет в наличии», CPX22 стоит €19,49 |
| **4VPS** и похожие (NL / DE) | 2 vCPU / 4 ГБ / 25 ГБ | ≈ $11,7 | карта РФ, СБП | в мае 2026 у 4VPS была атака на биллинг и сервера |

**Рекомендация:** Aeza в Нидерландах или Финляндии, 2 vCPU / 4 ГБ, оплата криптой (USDT/TON — у вас она и так
есть, и курс предсказуемый): около **€5 в месяц**. Если Aeza не устроит из-за санкций — любой европейский VPS
с такими же параметрами, Орбита от провайдера не зависит.

**Совместить с VPN:** на том же сервере можно поднять WireGuard / AmneziaWG. Тогда панель Орбиты открывается
только из вашего VPN (`http://10.8.0.1:8800`) и не торчит в интернет, а VPN заодно служит вам для личного
пользования. Нагрузка VPN на 1–3 устройства ничтожна.

Цены — с сайтов и обзоров на ноябрь 2026, перед покупкой проверьте на сайте провайдера.

## Установка (один раз, ~10 минут)

1. Купить VPS (Ubuntu 24.04), зайти по SSH под root.
2. Скопировать на сервер папку `deploy/` из репозитория (репозиторий закрытый, поэтому так) и запустить установку:
   ```bash
   scp -r deploy root@IP-сервера:/root/orbita-deploy      # с вашего ПК
   ssh root@IP-сервера bash /root/orbita-deploy/orbita install
   ```
   Установщик ставит Python и Node.js, создаёт пользователя `orbita`, папки, ключ шифрования секретов
   (`/etc/orbita/orbita.env`) и SSH-ключ только для чтения репозитория. Он покажет этот ключ:
   добавьте его в GitHub → репозиторий → Settings → Deploy keys (без права записи).
3. `sudo orbita deploy` — первая сборка и запуск Центра.
4. Перенести данные с ПК (ниже) или настроить ботов в панели с нуля.
5. Панель: `ssh -L 8800:127.0.0.1:8800 root@IP-сервера`, затем открыть `http://127.0.0.1:8800`, токен входа — `sudo orbita token`.

## Переезд с ПК без потерь

Важно: **ПК и сервер не должны работать одновременно** — один FunPay, один кошелёк TON, одна сессия Telegram.

1. На ПК закрыть Центр (значок у часов → «Выход»).
2. Положить `center/migrate.py` в `Documents\StarsCenter\app\center\` и выполнить в `Documents\StarsCenter`:
   ```
   runtime\python.exe app\center\migrate.py export --out %USERPROFILE%\Desktop\orbita.bundle
   ```
   Скрипт спросит пароль и упакует всю папку данных (`%LOCALAPPDATA%\StarsCenter\center-data`): настройки,
   базы, сессии Telegram, cookies Fragment, сид-фразу TON, секреты из `secrets.dat` (расшифрованные на ПК).
   Файл целиком зашифрован вашим паролем. После этого скрипт **выключает ботов на ПК**
   (копия прежних настроек — `center.yaml.before-orbita`).
3. Скопировать файл на сервер (`scp orbita.bundle root@IP:/root/`) и выполнить `sudo orbita import /root/orbita.bundle`.
   Секреты перешифруются ключом сервера. Файл переезда после этого удалите.
4. В панели проверить настройки и запустить ботов. Cookies Fragment и сессию FunPay иногда приходится
   обновить: сайты могут попросить войти заново с нового IP.

Вернуть всё на ПК: остановить сервер (`sudo systemctl stop orbita-center`), на ПК заменить `center.yaml`
копией `center.yaml.before-orbita`.

## Команды

| Команда | Что делает |
|---|---|
| `orbita status` | релиз, состояние Центра и каждого бота, последнее обновление |
| `sudo orbita deploy [ветка или sha]` | обновиться сейчас (то же, что делает таймер) |
| `sudo orbita rollback [релиз]` | вернуться на прошлый релиз, тоже на ходу |
| `orbita releases` | список релизов, `*` — текущий |
| `orbita logs [starsbot]` | журнал Центра или бота в реальном времени |
| `sudo touch /etc/orbita/auto-off` | выключить автообновление (удалить файл — включить) |
| `sudo systemctl stop orbita-center` | полная остановка: Центр мягко останавливает ботов |

Настройки — `/etc/orbita/orbita.env`: ветка (`ORBITA_BRANCH`), автообновление (`ORBITA_AUTO`),
сколько секунд бот должен проработать на новой версии (`ORBITA_VERIFY_SECONDS`), тесты перед установкой (`ORBITA_TESTS`).

## Безопасность

* Секреты (golden_key, Steam, токены Telegram) лежат в `secrets.dat`, зашифрованы ключом `CENTER_SECRET_KEY`
  из `/etc/orbita/orbita.env` (права 600, только root). **Сохраните этот ключ** в менеджере паролей: без него
  `secrets.dat` не расшифровать, а резервная копия бесполезна.
* Сид TON, cookies Fragment и сессии Telegram — в `/var/lib/orbita` (права 700, пользователь `orbita`).
  Центр и боты работают не от root, код релизов для них только для чтения, systemd закрывает им остальную систему.
* Панели слушают только `127.0.0.1`: доступ через SSH-туннель или VPN. Не открывайте порты 8800–8806 наружу.
* Вход на сервер — по SSH-ключу, вход по паролю лучше выключить (`PasswordAuthentication no`).
* Держите на кошельке бота только оборотные TON, как и на ПК.

## Docker

`docker compose up -d` по-прежнему работает (простой вариант), но в нём Центр и боты в одном контейнере:
обновление = перезапуск всего контейнера. Для обновления на ходу используйте systemd-вариант выше.
