# MannBot: автопродажа Mann Co. Supply Crate Key на FunPay

Бот продаёт ключи TF2 с вашего Steam-аккаунта через лоты FunPay. Он работает через **веб-страницы** обеих площадок, как браузер: FunPay через cookie `golden_key`, Steam через страницы steamcommunity.com и мобильные подтверждения.

## Как проходит сделка

```
Оплата на FunPay ──► бот пишет в чат заказа инструкцию (что прислать, как, меры безопасности)
       │
Покупатель присылает ссылку на обмен
       ├─ данные плохие (профиль, обрезанный token, устаревшая ссылка, трейд-бан, переполненный инвентарь)
       │      └─► «с вашими данными проблема: <причина>, нужны реальные данные» + повтор инструкции
       │          (после N попыток заказ уходит продавцу, покупателю уходит вежливое сообщение)
       ├─ задержка обмена (trade hold) ─► политика: попросить Steam Guard / отправить / спросить админа
       └─ всё ок ─► риск-скоринг ─► трейд-оффер с ключами + подтверждение Steam Guard
                                        │
          принят ─► «Сделка успешно завершена, спасибо! Пожалуйста, подтвердите заказ и оставьте отзыв»
          отклонён/истёк ─► «напишите !повтор»   отменён не нами ─► предупреждение об API-скаме
```

Просьба подтвердить заказ уходит **только после** того, как Steam сообщил, что трейд принят (правило FunPay 2.1.2).

## Возможности

| Блок | Что делает |
|---|---|
| **Сделка** | Инструкция после оплаты, разбор и проверка ссылки на обмен (через страницу `tradeoffer/new`: валидность token, трейд-бан, trade hold, имя аккаунта), отправка и подтверждение трейда, отслеживание статуса, повторы, напоминания, команды `!статус !повтор !продавец !помощь !отправить`, язык ru/en |
| **Безопасность сделки** | Подтверждается только своё подтверждение (по `creator_id` = id трейда, никаких «подтвердить всё»); сверка получателя и того, что мы ничего не запрашиваем; защита от двойной выдачи (идемпотентность и поиск «потерянного» трейда по `#заказ`); резервирование конкретных assetid; отклонение контрпредложений; отмена трейда при возврате денег; ключи выдаются, даже если покупатель подтвердил заказ раньше времени |
| **Безопасность аккаунта** | CRITICAL-алерт при исходящем трейде, созданном не ботом (по настройке такой трейд отменяется); алерт при пропаже ключей из инвентаря; авто-отклонение входящих трейдов, запрашивающих ваши предметы |
| **Правила FunPay** | Без контактов и уводов с площадки (отвечает шаблоном, п. 1.1 и 2.1.1); без сторонних ссылок, кроме steamcommunity.com (п. 1.12); вопросы не игнорируются: непонятное сообщение получает ответ и пересылается продавцу (п. 2.1.4 и 3.1.2); ограничение частоты сообщений (п. 1.9); наличие лота синхронизируется со складом, лот скрывается при нуле (п. 2.1.5) |
| **Риск-система (антифрод)** | Скоринг: чёрные списки (FunPay и SteamID), крупный заказ, первая покупка на большой объём, много заказов в сутки, история возвратов, один Steam-аккаунт у разных покупателей, trade hold. Результат: авто / ручное одобрение (`/approve`) / блок |
| **RTBA** (Real-Time Bid Adjustment) | Автоцена по публичной таблице лотов: стратегии top1/topN/median, шаг демпинга, пол «себестоимость + маржа + комиссия», потолок, отсев демпинг-выбросов (IQR) и мелких лотов, надбавка за дефицит, гистерезис и лимит изменений в час, автокалибровка «цена покупателя / цена лота» |
| **Лоты** | Синхронизация «Наличия» с инвентарём, автоподнятие лотов |
| **CRM** | Заказы (статусы, таймлайн событий, переписка, трейды, заметки), клиенты (LTV, ключи, SteamID, возвраты, чёрный список), ручные действия: одобрить / переотправить / выдан вручную / возврат / написать в чат |
| **Аналитика** | Выручка, прибыль, средний чек, воронка, медианы этапов (оплата → ссылка → трейд → принят → подтверждён), доля автоматических выдач, подтверждения, возвраты, причины сбоев, заказы по часам, история цен и конкурентов, склад, отзывы |
| **Рекомендации** | Склада хватит на N дней, медленные ссылки, много ошибок данных, частые trade hold, низкая доля подтверждений, ценовая война ниже себестоимости, нет продаж, плохие отзывы, ещё включён dry_run и т. п. |
| **Уведомления** | Telegram + журнал алертов; CRITICAL при: слетела сессия FunPay или Steam, склад пуст при оплаченном заказе, трейд не подтвердился, чужой трейд, пропажа ключей, возврат после выдачи, сбои циклов. Антиспам (throttle). Управление командами из Telegram |

## Готовое приложение

MannBot — приложение с интерфейсом в браузере. Настраивать YAML вручную не нужно: всё делается в мастере настройки.

| Вариант | Для кого | Как запустить |
|---|---|---|
| **Windows, портативный** `MannBot-Windows-x64-portable.zip` | Свой ПК, без установки Python | Распаковать → `MannBot.bat` (или `MannBot (без окна).vbs`). Демо: `MannBot DEMO.bat` |
| **Windows, один файл** `MannBot.exe` | То же, одним exe | Собирается `packaging\build_windows_exe.bat` на Windows или в GitHub Actions (`.github/workflows/build.yml`) |
| **Linux, один файл** `dist/linux/MannBot` | Linux-ПК | `./MannBot` (демо: `./MannBot --demo`) |
| **Docker / VPS** | Работа 24/7 | `docker compose up -d`, панель через `ssh -L 8080:127.0.0.1:8080 vps` |

Что внутри приложения:

* **Мастер настройки**: golden_key, ID лотов, загрузка **maFile** кнопкой, Telegram. У каждого шага есть кнопка «Проверить»: вход на FunPay, вход в Steam и наличие ключей, доступ к подтверждениям, тестовое сообщение в Telegram.
* **Кнопки «Запустить», «Пауза», «Остановить», «⏻ Выход»**, статус бота в шапке. Переключение тестового и боевого режима одной кнопкой.
* **Настройки**: все параметры (сделка, риск, RTBA, безопасность, уведомления, SLA) с подсказками. Секреты не показываются: пустое поле означает «не менять».
* **Сообщения**: редактор всех текстов покупателю (ru/en) с предпросмотром и проверкой переменных, сброс к стандартному тексту.
* **Журнал** в реальном времени, CRM, аналитика, цены и алерты, как раньше.
* Вход в панель защищён токеном. Приложение само открывает браузер уже залогиненным. Вторая копия не запускается: просто откроется окно первой. Если порт занят, приложение выберет соседний.
* Все данные (`config.yaml`, база, журнал) лежат в папке рядом с программой (`data\` или `MannBot-data/`). Перенос и резервная копия — простое копирование папки.

Сборка самому:

```bash
python packaging/build_windows_portable.py        # → dist/MannBot-Windows-x64-portable.zip (можно собирать на Linux)
pyinstaller packaging/mannbot.spec                # → dist/MannBot(.exe) для текущей ОС
```

## Поставка ключей Telegram-магазину (ShopBot)

MannBot отдаёт ключи и магазину экосистемы по контракту `/api/supply/*` (как StarsBot): заказ `SHOP-<ref>` идёт
тем же путём, что и заказ FunPay (склад, резерв assetid, Steam Guard, реестр обменов с LisBot, защита от двойной
выдачи), но без чата FunPay — покупателю пишет ShopBot. Включение: `supply.token` (≥16 символов) в config.yaml
MannBot и тот же токен в `suppliers.steam_keys.token` ShopBot; себестоимость для котировки — `rtba.cost_per_key`.
Ошибка данных покупателя или отклонённый трейд закрывают заказ (ключи возвращаются на склад), ShopBot просит новую
ссылку и присылает новый заказ.

## Установка из исходников


## На одном аккаунте FunPay со StarsBot

* **golden_key** и Telegram-уведомления берутся из настроек StarsBot (`funpay.share_from`, по умолчанию
  `../starsbot/config.yaml`), если у MannBot свои пустые. Команды Telegram при этом слушает только StarsBot.
* **Лот** можно не указывать: при старте бот находит ваш лот с ключами в разделе TF2 → «Предметы» или выставляет
  новый (`funpay.auto_create_lot`, тексты `lot_title_*`/`lot_desc_*`). В тестовом режиме новый лот выключен.
* **Чаты**: runner FunPay на живом аккаунте присылает список диалогов только в первый раз, поэтому бот берёт его со
  страницы `/chat/` и отдельно читает чаты заказов, где ждёт ссылку на обмен.
* **Вопрос без заказа** о ключах/TF2 получает один шаблонный ответ (`presale_keys`); общий файл координации следит,
  чтобы второй бот в этот чат не отвечал. Звёзды и подарки — темы StarsBot и TG Gift, MannBot там молчит.

## Где взять данные

* **`golden_key`**: cookie сайта funpay.com из браузера (DevTools → Application → Cookies). Это ключ от вашего аккаунта, никому его не передавайте.
* **`node_id` / `game_id`**: Team Fortress 2 → «Предметы» = `1808` / `435` (указаны в примере конфига). **`offer_id`**: id вашего лота из ссылки `funpay.com/lots/offer?id=…`.
* **Steam**: `shared_secret` и `identity_secret` берутся из maFile (Steam Desktop Authenticator). Вместо логина и пароля можно указать `login_secure_cookie` (cookie `steamLoginSecure` со steamcommunity.com), но для подтверждения трейдов `identity_secret` нужен всё равно.
* **Telegram**: токен бота от @BotFather, ваш `chat_id` (например, через @userinfobot).

Все секреты можно передавать через переменные окружения: `${FUNPAY_GOLDEN_KEY}` и т. д.

## Первый запуск, безопасно

1. Оставьте `dry_run: true`: бот всё читает и пишет в CRM, но ничего не отправляет. Проверьте в панели, что заказы и чаты распознаются.
2. Заказы, оплаченные **до** первого запуска, бот не выдаёт сам: они попадают в «ручные». Передать такой заказ боту: `/take ID`.
3. Выключите `dry_run`, проведите 1–2 тестовые продажи. RTBA включайте после того, как укажете `cost_per_key`.

## ИИ-агент для покупателей

Когда бот не понял сообщение покупателя (вопрос, просьба, жалоба), раньше оно только пересылалось продавцу. Теперь его может обработать ИИ-агент на Claude API (`mannbot/ai/`):

* пишет черновик ответа по фактам заказа (статус, число ключей, получена ли ссылка), истории чата и тону продавца;
* **режим `suggest`** (по умолчанию): черновик приходит продавцу в Telegram и на страницу «ИИ-ответы» панели. Отправить: `/aiok N`, свой текст: `/aiedit N текст`, не отвечать: `/aino N`, список: `/ai`. Покупатель тем временем получает прежний шаблонный ответ;
* **режим `auto_safe`**: безопасные темы (`ai.auto_topics`: статус заказа, где взять трейд-ссылку, как получить обмен) уходят покупателю сразу, если уверенность не ниже `ai.min_confidence`. Возвраты, жалобы и всё непонятное всегда идут продавцу;
* каждый ответ перед отправкой проверяется кодом на правила FunPay: никаких ссылок кроме steamcommunity.com/funpay.com, контактов и общения вне площадки, просьбы подтвердить заказ до выдачи ключей, запроса паролей/кодов/API-ключа, обещаний возврата и скидок. Ответ с нарушением не уйдёт ни автоматически, ни по `/aiok`;
* журнал всех ответов и оценка качества: доля одобренных без правок, исправленных, отклонённых, остановленных проверкой, оценки 👍/👎 продавца, задержка и токены. JSON для центра: `GET /api/ai`.

Включение: «Настройки» → «ИИ-агент для покупателей» → включить, вставить API-ключ Claude (console.anthropic.com). Без ключа агент выключен и бот работает как раньше. В демо-режиме используется заглушка без сети. Модель по умолчанию `claude-opus-5-5` с низкой глубиной размышления (`ai.effort: low`).

## Команды Telegram

`/status /orders /stock /report /pause /resume /approve ID /reject ID /resend ID /refund ID /delivered ID /take ID /msg ID текст`

ИИ-агент: `/ai /aiok N /aiedit N текст /aino N`

Команды принимаются только из `admin_chat_ids`.

## Структура

```
mannbot/
  funpay/   client.py (runner, чат, заказы, лоты, поднятие, возврат), parsers.py (вся разметка FunPay)
  steam/    client.py (вход, инвентарь, трейды, подтверждения), tradelink.py, guard.py (2FA)
  core/     engine.py (жизненный цикл заказа), messages.py (тексты ru/en), risk.py, rtba.py, models.py
  crm/      db.py (SQLite)
  ai/       agent.py (ИИ-агент: черновики, автоответ, журнал, качество), backends.py (Claude API, заглушка), guard.py (правила FunPay)
  analytics/analytics.py (KPI + рекомендации)
  notify/   notifier.py (Telegram, алерты, команды)
  app/      launcher.py (запуск приложения), supervisor.py (старт/стоп бота, настройки, проверки), schema.py
  web/      server.py + templates (интерфейс, SVG-графики без CDN)
  demo.py   эмуляторы FunPay и Steam
packaging/ сборка exe, портативной Windows-версии; Dockerfile, docker-compose.yml
```

## Важно

* Вёрстка FunPay и Steam со временем меняется. Все селекторы FunPay собраны в `funpay/parsers.py` и покрыты тестами на фикстурах: при поломке правится одно место.
* Статусы трейдов читаются через `IEconService` с `access_token` из сессии. Если Steam начнёт это отклонять, укажите `steam.api_key`.
* Держите на аккаунте мобильный Steam Guard, иначе у ваших трейдов будет задержка. Не используйте этот аккаунт для ручной торговли, или выключите `security.cancel_foreign_offers`.
